# 🔧 KVM 物理端口映射逻辑说明

## 1. 背景描述
在早期的版本中，系统通过 SNMP 遍历（WALK）终端表时，直接使用数据的**行号 (Row Index)** 作为端口号。但在实际硬件中，SNMP 表的行顺序可能因模块插入顺序而变化，导致大屏显示的槽位与物理面板不符。

## 2. 核心逻辑 (The Fix)
系统现在统一采用 **“基于硬件字段的物理定位”** 策略。

### 后端采集 (Backend Poller)
1. **OID 识别**：针对 CPU 表和 CON 表，明确定义并读取 **Column 1 (Index)**。
   - CPU 表基础 OID 路径中的 `.1` 列。
   - CON 表基础 OID 路径中的 `.1` 列。
2. **端口号提取**：
   - 轮询器在解析每一行数据时，会优先提取 `Column 1` 的数值。
   - 该数值直接存入数据库 `endpoints.index` 字段。
   - 示例：如果 SNMP 第 1 行的 `Column 1` 值为 `5`，则该模块被记录为 **#Port 5**。

### 前端渲染 (Frontend MatrixView)
1. **全量网格生成**：
   - 系统不再仅仅根据“已发现的终端列表”循环渲染。
   - 系统首先根据交换机的总端口数（通过 `Device.last_metrics.ports` 字典的键值对数量或配置）生成一个全量网格。
2. **位置匹配**：
   - 前端通过遍历网格索引（1 到 32），检查是否有终端的 `index` 属性与之匹配。
   - **有匹配**：渲染对应的 CPU/CON 模块小方块。
   - **无匹配**：渲染“空置 (EMPTY)”槽位（灰色虚线框）。

## 3. 特殊状态处理：CON 模块 USB 链接
在之前的版本中，当 CON 模块未插入 USB 设备时，SNMP 会返回 `none`，前端逻辑会因为该值为“空”而直接隐藏整行 UI，导致用户误以为系统不支持 USB 监控。

### 改进方案：
- **数据保留**：后端现在完整保留 `con_console_usb` 字段，即便其值为 `none`。
- **显式展示**：前端 `EndpointDetail.jsx` 移除了隐藏逻辑。如果状态为 `none`，UI 会明确显示 **“控制台 USB：未连接”**。
- **状态翻译映射**：
  - `none` ➡️ `未连接 (Not Connected)`
  - `keyboard` ➡️ `键盘 (Keyboard)`
  - `mouse` ➡️ `鼠标 (Mouse)`
  - `keyboard+mouse` ➡️ `键盘 + 鼠标`

## 4. 运维影响
- **更换插槽**：如果运维人员将服务器从 1 号口换到了 8 号口，只需触发一次轮询，大屏上的方块会自动从 1 号位置“跳”到 8 号位置。
- **视觉一致性**：大屏上的网格布局现在与机房内 KVM 交换机的物理背板孔位完全一一对应。
