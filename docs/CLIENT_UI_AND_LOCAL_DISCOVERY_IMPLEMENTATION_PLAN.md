# 客户展示版 UI、设备清单与本机发现实施说明

> 日期：2026-08-02  
> 目标：以可回退的客户展示版增强现有 KVM Dashboard；不改变 SNMP/MIB 采集语义，不以静态假数据充数。

## 1. 参考与范围判断

本说明基于用户提供的 KVM 状态总览参考图，以及
`I:\tempdownload\监控截图.docx` 中的九张界面截图。后者是图片型 Word，
无法提取结构化文本；已从截图确认的可复用信息架构为：深蓝监控台、设备类型
Tab、搜索/状态筛选、可横向滚动的核心状态表、点击后的右侧详情、告警中心、
声音设置、设备自动发现和操作日志。

不复制不可维护或无数据来源的部分：3D 环图、地形柱状图、虚假的总数、固定设备
属性列，以及与现有路由不兼容的完整侧边栏后台壳。

## 2. 任务 A：客户展示版总览（可切回旧版）

### 设计

- 在 `/dashboard` 提供 `经典视图` 与 `监控总览` 两个可见切换项，选择持久化在
  浏览器本地；经典视图保留现有布局和行为，作为随时可用的回退路径。
- 新视图采用深蓝、青色健康态、琥珀/红色异常态的监控台样式，但使用普通 CSS、
  SVG/CSS 进度图和现有 lucide 图标，不引入大屏/3D 图形依赖。
- 顶部显示真实 KPI：设备总数、在线、离线、活动告警和 WebSocket 状态。
- 主区使用真实 `devices` / `endpoints` / `alerts`：设备健康概览、CPU/CON/MUX
  分布、近期告警、矩阵入口与设备列表入口。任何不可从当前数据计算的数字显示
  `—`，不写示例值。

### 验收

1. 两个视图切换后均不触发额外后端写操作，刷新后保持选择。
2. 新视图的 KPI 与当前 store 数据一致；点击设备/告警仍走已有详情或筛选路径。
3. 在 1440px 宽度和窄屏下无横向页面溢出；经典视图完整可回退。

## 3. 任务 B：按设备类型的状态清单与详情

### 设计

- 在现有设备列表上方增加 `全部 / 矩阵 / CPU / CON / DWC / MUX` Tab；Tab 依据
  profile role 与现有 profile metadata 动态出现，不写死单一厂商型号。
- 每个 Tab 显示共有核心列：设备、型号/Profile、地址、在线、数据新鲜度、健康、
  实体数、活动告警、最近检查。仅在当前 Tab 对应 Profile 已有字段时显示扩展状态
  列，例如温度、网络、键鼠/USB、视频/显示、SFP；缺失则不伪造。
- 点击一行复用现有 `GET /api/v1/devices/{id}` 详情抽屉，按后端 sections/entities
  展示完整状态；不另建与 MIB 字典脱节的详情接口。

### 验收

1. CPU/CON/DWC/MUX 数据不再被矩阵筛选隐藏；每个 Tab 的计数与筛选结果一致。
2. 行点击与“查看详情”均请求同一设备详情，能展示实际 fields 与 entities。
3. 没有相应 Profile 的 Tab 可禁用/隐藏，页面不因此报错。

## 4. 任务 C：告警声音与本机回环发现

### 设计

- 声音沿用 Web Audio，不上传或写入用户音频。界面必须呈现浏览器自动播放限制：
  用户点击“试听”后将 AudioContext 解锁并更新 `ready/blocked` 状态；新告警只在
  未静音、对应严重度开启、去重/节流通过时播放。
- 发现服务接受 IPv4 CIDR；`127.0.0.0/24` 合法，扫描范围是 `.1`–`.254`，因此可
  用 `127.0.0.2` 等本机回环地址和 SNMP 161 端口测试。`.255` 是该 `/24` 的广播
  地址，不扫描；需要单个地址时使用 `/32`。
- 不扩大扫描范围、不绕过 256 hosts 上限、不把 SNMP community 返回给浏览器。

### 验收

1. 前端单元测试覆盖声音开关、首次告警、重复告警、节流和浏览器阻止路径；浏览器
   中手动点击“试听”后显示 ready 或明确 blocked，而非静默失败。
2. 后端测试覆盖 `127.0.0.0/24` 以及 `/32` 通过校验、`.255` 未在 `/24` hosts 中；
   isolated SNMP Agent 绑定 `127.0.0.2:161` 时，发现任务识别并导入它。
3. 运行中的用户服务和 UDP 端口不得被测试强制停止；如 161 已被占用，改用独立
   临时端口的单元/集成测试并报告限制。

## 5. 交付顺序与责任边界

1. A、B、C 可并行，分别拥有独立组件/样式或后端服务文件。
2. 每项完成后必须运行对应 lint/test/build；随后由主任务做一次合并后的浏览器和
   API 验收。
3. 不提交运行产生的数据库 WAL/SHM、轮询日志或临时拓扑文件。
